01The problem

Refund rules for a cancelled flight are scattered across airline fare rules and government regulations, written in dense legal language. A plain LLM will answer confidently and sometimes wrongly, with nothing to check it against.

The goal was answers you can trust: every response grounded in a specific source passage and cited, so a reader can verify it. That is a retrieval problem first and a generation problem second.

02Architecture

Two phases. Ingest runs offline: policy PDFs are parsed to a structured markdown vault, chunked, embedded, and stored in PostgreSQL. Query runs online: a question is embedded, matched against the vector store, and answered by a local LLM that quotes its sources.

03Four retrievers, head to head

Retrieval quality makes or breaks a RAG system, so I built four versions and measured them against a golden set, rather than assuming more sophistication is automatically better.

Naive vector search

Straight cosine similarity over the embeddings. A baseline to measure everything else against.

Hybrid (BM25 + vector)

Fuses lexical BM25 with dense vector search via reciprocal rank fusion, so exact-term matches that pure embeddings miss still surface.

Reranked

Takes the hybrid candidates and reorders them with a cross-encoder reranker, which reads query and passage together for a sharper relevance judgment.

Metadata self-query

Uses the YAML frontmatter (airline, jurisdiction, doc type, topic) to filter before ranking, so a question about one airline in one country doesn't retrieve another's rules.

04Results

I scored each retriever on a golden set (recall@5, MRR, hit-rate, latency). The result was a surprise: two of the four "upgrades" made retrieval worse.

Retrieverrecall@5MRRhit-ratelatency
v1 · naive (vector)0.670.650.800.08s
v2 · hybrid (BM25 + vector)0.600.610.700.09s
v3 · reranked (cross-encoder)0.690.830.907.95s
v4 · metadata (LLM filter)0.430.420.501.06s

Plain vector search (v1) was already strong at recall@5 0.67. Cross-encoder reranking (v3) was the clear winner on ranking quality (MRR 0.83, hit-rate 0.90), but at a real latency cost (~8s). Hybrid search added ranking noise, and metadata self-query over-filtered on semantic questions. The lesson: measure, don't assume more sophistication helps.

On 5 deliberately unanswerable questions, the system correctly declined 4 (80%) with grounded refusals instead of hallucinating an answer. Knowing when not to answer is part of being trustworthy.

Next: isolate generation from retrieval by swapping the local 3B model for a frontier model, to separate synthesis errors from retrieval failures.

The golden set is n=20 answerable (+5 unanswerable), growing toward ~50, so these numbers are directional.

05Design choices

Local-first, zero API keys

Embeddings (bge-small-en) and generation (Ollama llama3.2) both run locally, so the system works with no external services or keys. Claude is an optional drop-in for the LLM.

Runs fully offline; cheap to iterate

A structured, version-controlled corpus

Policies live as a markdown vault with YAML frontmatter, which is what makes metadata filtering possible and keeps the corpus git-diffable, so a policy change is a reviewable commit.

The knowledge base is auditable and trackable

An educational portfolio project with no airline affiliation. It provides no legal advice; source documents were downloaded locally for educational use only.
